Support keeps escalating pricing complaints against the pricecache service (this repo). Every so often, after we change a price or an FX rate, some customers keep getting the old price for minutes afterwards, even though updates are supposed to show up immediately. We think the TTL/expiry handling in the cache is broken. A smaller number of customers are also being quoted surcharges they never asked for (rush or gift wrap they didn't pick, the wrong promo), and under load the request counters on the stats dashboard don't add up. Please track down the real causes and fix them. Keep the design as it is: cache loads for different keys must still run in parallel, and a write must never wait for an in-flight read. The public API and the existing behaviour (TTL, LRU eviction, stats names) must not change.
