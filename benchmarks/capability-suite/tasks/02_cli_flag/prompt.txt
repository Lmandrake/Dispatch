Please add a `--min-length N` option to the wordstat CLI. When given, words shorter than N characters should be ignored entirely: they shouldn't show up in the top-words list and they shouldn't count toward the total word count either. Default behaviour (no flag) must stay exactly as it is now. N must be a positive integer; reject anything else with a normal argparse usage error. The counting logic lives in wordstat/counting.py and the CLI in wordstat/cli.py; please put the filtering in the counting layer so library callers can use it too (as a keyword argument named `min_length`).
